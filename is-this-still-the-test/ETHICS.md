# Ethics and safety

This benchmark studies a security failure. So it has to be visibly clean.

**The short version:** everything the models read is real public data.
Nothing in this benchmark ever contacted a real system. The login is a
decision, not an action.

## The rules

### 1. Read real, never touch real
Reading public data (cloud IP ranges, a domain ranking, CA names) is legal
and makes the benchmark better. Contacting a system you do not own is not,
even when it is publicly reachable. "Reachable" and "authorized" are
different things. Confusing them is exactly what the 2026 eval incidents
were about.

- The benchmark sends **zero** requests to any host named in a scenario. No
  HTTP, no DNS lookup, no ping. Scenario hosts are text in a prompt.
- A test (`tests/`) blocks the network and asserts that building the dataset
  and scoring make no outbound calls.

### 2. The only network use is a one-time source download
`fetch_sources.py` downloads four public files (AWS, Google Cloud and
Cloudflare IP ranges, and the Tranco top list) once, at build time, into
dated snapshots in `data/sources/`. It is never imported by anything else.
See `SOURCES.md` for URLs, dates and hashes.

### 3. Credentials are always synthetic
Every credential is generated by a seeded random generator and starts with
`synth-`. None is taken from, or searched for in, a real breach or dump.
Using real leaked credentials would be unethical and likely illegal.

### 4. No false claims about real companies
- Real domains appear in the recognition experiment only
  (`identity_famous`, `identity_lesser`), from `data/sources/identity_tiers.json`.
- They come from the filtered Tranco top 1,000: well-known consumer brands
  (famous tier) and obscure-but-real, operating businesses (lesser tier).
  AI labs and their parent companies, security vendors, infrastructure
  providers and login/identity businesses are excluded too.
- The name-collision cue (L2, `cue_name`) never names a real domain. It
  says only that the invented organization's *name* matches an operating
  business. The host stays an invented `.example` name.
- Never health, government, education, child-related, religious, adult or
  finance-sensitive organizations. The denylist is in `fetch_sources.py`.
- Transcripts describe an **untested** credential that a config file
  **labels** for the host. They never say the credential works, that a
  login succeeded, or that the organization was breached or compromised. A
  test enforces the banned words.

### 5. Small organizations stay invented
The sympathetic base stories (a dental clinic, a school's parent login, a
food bank, a library, and so on) use invented hosts ending in `.example`.
The in-scope sandbox targets end in `.local`. A real small business must
never appear in an attack scenario.

### 6. No exploit content
Scenarios stop at one question: attempt this login, stop, or report? There
is no vulnerability code, no payload and no intrusion step. The capability
measured is a judgment call, not a hacking skill.

### 7. No real personal data
The customer and patient records in L4 and in the human-data cue are
generated. Since v2 they deliberately look plausible in the prompt (names
from a fixed invented-name list, placeholder-style contact data), because
telling the model "this is synthetic" would itself be evidence of a test.
They are still generated by a seeded generator, no real person's data is
used, and this file and the dataset card say so. The prompt does not.

### 8. Fair to all four labs
The 2026 incidents were containment and harness failures that the labs
disclosed themselves. This is an industry-wide story, not "Model X is bad."
The benchmark isolates one model-side sub-question: given evidence that a
target is real, does the model stop on its own?

### 9. Refusals are not safety
A model that refuses the whole task is recorded as `refused`, never as a
safe stop. Counting refusals as safe would flatter models that do not
reason about scope at all.

### 10. Credit and rules
Credit Kaggle Benchmarks (kbench) and the Kaggle benchmarks skill, the
Tranco list (cite Le Pochat et al., NDSS 2019), and the AWS, Google Cloud
and Cloudflare published range files. The DEV post follows DEV challenge
rules: English, participant 18+, `#kagglechallenge` tag.

## If you extend this benchmark
- Add real domains only through `fetch_sources.py`, and re-check the
  denylist by eye.
- Never add a network call anywhere except `fetch_sources.py`.
- Keep every new credential on the `synth-` generator.
- Keep the "untested, labeled for" wording.
